# 1.0.4 下课前提醒审查与修复

用户反馈：在设置的下课前 10 分钟，顶部没有这门课的流体云。本次审查处理实际后台调度、关闭提醒的行为和再次提示的方式；不只检查预览按钮。

## 确认的实现缺口

1. 原先关闭课前或课中的云，会把整次课程加入关闭列表，下课前阶段也一起被过滤。现在普通显示与下课提示使用独立关闭记录，旧版普通关闭记录也不会屏蔽下课提示。关闭总提醒开关仍会停止全部提醒。
2. 原先下课前只是更新同一条静音通知。现在到节点时以独立通知 ID 发布“快下课 · 课程名称”，并使用独立的高重要性“下课前提示”通知分类，请求系统突出显示。默认保持无声音、无振动，不改写用户对原分类或新分类的设置。
3. 分钟刷新可能与唤醒提醒同一时刻触发，立即把刚发布的提示更新成静默状态。现在遇到同一或更早的提醒边界，不再安排多余的分钟刷新。
4. 预览原先会覆盖真实课程的下一次唤醒。现在保留真实边界，真实下课提示到期时优先结束预览并提示。

停止按钮及划掉操作绑定课程、阶段和预览实例，旧卡片延迟送达的关闭操作不会关闭新出现的下课提示。已发送的下课提示记录持久保存，普通刷新和重启不会反复突出显示。

## 现在的行为

以当天 08:00–09:25 的课程、课前和下课前均提前 10 分钟为例：

| 时刻/操作 | 结果 |
| --- | --- |
| 07:30 配置课程 | 排入 07:50 唤醒及之后的课程边界 |
| 07:50 | 出现课前流体云，系统计时器指向 08:00 |
| 提前收起课前/课中提醒 | 关闭当前普通显示，保留 09:15 下课提示唤醒 |
| 09:15 | 新发一次“快下课 · 课程名称”，计时器指向 09:25 |
| 后续分钟刷新、恢复应用或重启 | 更新进度，不反复突出显示本次提示 |
| 结束下课提示 | 本次下课提示不再返回，后续课程不受影响 |
| 09:25 | 课程提示撤下，系统超时也以真实下课时刻为界 |

下课提前量仍可自定义为 1–1440 分钟；超过课程长度时，从上课开始显示下课提示。一次性日程没有课程下课提示。同一时刻只保留一张课程流体云：新到期且未提示的下课阶段优先，其他已提示的下课阶段按结束时刻排序，平时保留最早开始的课程。

顶部收起与展开继续使用系统倒计时，不重新加入“14分上课”等固定分钟文字。

## 手机上如何核对

[下载 1.0.4 ARM64 APK](https://github.com/kitty191/schedule/raw/refs/heads/builds/android-v1.0.4/downloads/today-courses-v1.0.4-arm64.apk)，可覆盖原版，保留课程和设置。

“我的 → 提醒设置”新增：

- **下课提示通知**：是否允许此通知分类；分类被降为普通重要性时提示开启横幅。
- **下次下课提示**：从真实课程计算出的下一次触发时刻，不使用预览时刻。
- **最近下课提示**：触发时间、课程和“已提交系统 / 未发送”结果，仅记录真实下课提示。

请允许“准时提醒权限”，并在系统通知设置中允许本应用“下课前提示”分类及横幅。缺少准时权限时使用系统允许的非精确唤醒，实际触发可能延后；应用不能绕过系统权限。“已提交系统”只表示通知发布成功，不代表 ColorOS 已显示胶囊或横幅。ColorOS 的顶部显示、横幅及省电行为仍须 OPPO 真机确认，云环境无法代替这项验证。

## 验证

Robolectric 后台测试使用实际 Android 24/36/37 框架与 Manifest 中的广播接收器，通过系统调度的 PendingIntent 触发；测试时钟推进期间不打开 Flutter 页面、不调用预览按钮。

覆盖：关闭课前云后在真实下课节点提示；新通知 ID、标题、重要性与持续倒计时；只提示一次；重启恢复；单独关闭下课提示；分钟刷新边界去重；手动每周课程与导入的固定日期；自定义提前量和短课；权限被拒与分类被关闭；旧关闭操作晚到；其他课程或预览占用；关闭总开关与下课清理。另检查提醒设置展示及旧系统通知回退。

实际流体云外观和手机的省电限制不属于这些框架测试所能验证的范围。
