# 1.0.6 流体云进度提醒

1.0.6 补充计时终点的系统到期保护和独立课中通知，修复上课时点后旧课前云可能长时间停在 `00:00` 的问题；[详见到零审查](COUNTDOWN_BOUNDARY_FIX.md)。保留 1.0.5 的[独立后台排程](BACKGROUND_REMINDERS.md)。

新版继续沿用原包名和公开 Android Live Updates 接口，保留原普通提醒分类。1.0.4 将下课前阶段改为独立提示分类和通知 ID，修复收起普通云后漏掉下课提示；[详见后台审查](ENDING_REMINDER_FIX.md)。

## 显示内容

课前示例（这是内容示意，实际排版由手机系统决定）：

```text
课前 · 第 3–4 节 · 第 8 周             系统倒计时
08:30 上课  ·  10:05 下课
大学英语 · 东校区综合楼 B402
灰色课前段 ━━ 开课节点 ━━ 紫色上课段
```

- 进度覆盖“开始提醒 → 上课 → 下课”，两段长度按真实持续时间计算，书本图标跟随进度移动。
- 顶部收起与展开共用系统倒计时：课前指向上课时刻，上课后指向下课时刻。顶部数字由系统持续绘制，格式由手机决定，可能是“07:43”，无需点开或让 App 逐分钟刷新文字。上课、快下课等状态在展开卡片中显示。
- 到用户设置的下课提前量时，独立发布一次“快下课 · 课程名称”提示，使用下课沙漏图标，之后静默更新计时，下课撤下提醒。一次性日程使用“开始 / 进行中 / 结束”，不显示课程节次或下课状态。
- 节次来自手动绑定，或与课表设置完全匹配的起止时间。自定义时间不匹配、实际本地时刻因时区变化不再匹配时省略节次。教学周使用学期日期及每周起始日计算，未设置或学期尚未开始时省略。
- 修改每周起始日会立即同步提醒的教学周；仅修改课表显示高度不会重新调度。清除学期日期也会正确清除数据库旧值。

## 与参考图的区别

参考图是 iOS 的自定义实时活动。Android 的公开上岛接口使用系统模板，不能指定同样的黑底、卡片圆角、左右文字位置和独立教室胶囊。新版提供紫色进度、开课节点与跟随图标，文字颜色由系统处理以兼容浅色、深色和厂商主题。ColorOS 是否展示所有字段、如何排列和使用颜色，需在 OPPO 真机上确认。

不使用悬浮窗或自定义 RemoteViews 替代流体云。自定义通知布局会失去公开 Live Updates 的提升资格。Android 16 首发实现与后续系统的 colorized 判定不同：优先按当前公开文档构建，再通过 `hasPromotableCharacteristics()` 检查；仅在系统要求旧规则且检查通过时使用旧规则。保留原普通渠道 ID 及用户通知权限设置，下课前阶段使用新的“下课前提示”分类。

Android 24–35 保留普通持续通知，展开提供完整文字和普通进度条。iOS 仍使用普通本地通知，本次没有加入 ActivityKit。

## 收起倒计时停住的修复

1.0.2 及更早版本同时设置了系统计时器和 `shortCriticalText`。例如“14分上课”是通知发送时计算的固定字符串，系统优先将它用于顶部胶囊。后台分钟刷新被延后时，这段文字可能不变；展开后的 Chronometer 仍按真正的上课时间计时，因此会出现两处不一致。

1.0.3 删除该固定文字来源，明确开启系统时间显示，保留 `when`、`usesChronometer` 和 `chronometerCountDown`。即使没有收到 App 的分钟刷新，计时目标仍是同一个绝对时间；展开不会重置倒计时。上课阶段继续显示距离下课的倒计时，阶段文案在展开卡片中展示。进度刷新与计时分开，仍不会为了更新数字每分钟唤醒手机。

## 真机查看

1. 安装 [1.0.6 ARM64 APK](https://github.com/kitty191/schedule/raw/refs/heads/builds/android-v1.0.6/downloads/today-courses-v1.0.6-arm64.apk)，可覆盖之前正式测试版，保留课程和设置。
2. 打开“我的 → 提醒设置”，检查通知和顶部实时提醒权限。
3. 点“发送课程预览”后回到桌面，先不要点开流体云，观察至少 1–2 分钟并对照手机时钟；确认收起数字继续减少后再展开，核对剩余时间。下课预览同样先保持收起，检查倒计时及自动撤下。
4. 检查真实课程在所设的课前、下课前边界切换，并在下课时撤下。

预览保留所选课程的名称、地点和节次，使用模拟时刻，明确标注“预览”。时间和进度不会在每次刷新时重新起算。倒计时归零或最多 5 分钟后结束；预览不修改课表。长下课提前量仍会显示下课阶段，跨日预览注明“次日”。升级时尚未结束的旧版预览会转换为新时间格式。

进度每分钟通过不唤醒手机的 RTC 刷新，倒计时由系统绘制；课前及下课前等提醒边界仍用原有的 AlarmManager 唤醒调度。休眠及省电策略可能延后进度刷新，不会为进度增加每分钟唤醒。普通显示与下课提示分开记录关闭状态：提前收起普通云不影响下课提示；关闭下课提示后本次不再返回。

## 检查

- Flutter 静态分析无问题，交互/数据测试覆盖提醒权限、状态展示及已有功能。
- Kotlin / Robolectric 测试覆盖日程规划、连续进度、提醒边界、零提前量、文件提醒、节次和教学周、时区及夏令时、模拟预览测试。
- Android 36、37 原生计时器回归测试：仅创建一次通知，未重新发送或展开时推进 6 分钟，验证约 14 分钟减少至约 8 分钟；另覆盖模拟休眠后恢复显示，以及旧固定文字被新通知清除。使用普通收起通知的原生视图作为测试宿主，并非 OPPO 流体云真机。
- Robolectric 使用实际 Android 24、36、37 框架构建通知，检查进度模板、字段、节点和图标、倒计时、提升资格及旧系统回退。测试遵守会话代理和 CA 信任配置。
- ARM64 release 构建、Android lint、包名/版本/原开发签名及 APK 对齐检查。

这些检查不能代替 OPPO 的流体云、权限弹窗和省电行为真机验证。
