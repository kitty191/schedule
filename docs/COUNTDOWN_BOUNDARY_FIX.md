# 上课后停在 00:00：1.0.6

用户在旧版观察到 15:10 上课时顶部计时归零，15:18 仍显示 `00:00`。用户尚未安装 1.0.5。本次检查也发现 1.0.5 仍缺少计时终点的通知到期保护，因此单纯增加上课闹钟并不足以防止旧卡片保留。

## 原因与改动

系统 Chronometer 负责显示倒计时，不会在到零时自动改变课程状态。旧实现课前计时目标为上课时刻，但 `setTimeoutAfter` 一直设置到下课时刻；如果上课回调迟到，旧通知就仍在有效期内，系统可能继续显示归零的计时。截图无法证明该手机具体为何没有完成切换；后台拦截、权限、空闲调度或厂商刷新行为仍需真机核对。

现在每条通知的系统有效期限制为 `min(本次显示截止时刻, 当前倒计时终点)`。每次分钟刷新都重新计算剩余时间，绝对终点保持不变。

| 场景 | 倒计时终点 | 系统到期时刻 |
| --- | --- | --- |
| 课前 | 上课 | 上课，或更早的预览截止时间 |
| 课中 | 下课 | 下课，或更早的预览截止时间 |
| 下课前提示 | 下课 | 下课，或更早的预览截止时间 |

上课时从原课前 ID `1001` 切换为独立课中 ID `1003`，下课前仍为 `1002`。先发布新阶段，再清理旧阶段。旧课前卡片到期撤下不会取消新课中的计时，系统界面也能将其视为新的计时实例。关闭提醒、禁用提醒和结束课程会清理三个 ID；状态查询支持新 ID。

正常回调示例：14:55 课前计时指向 15:10 → 15:10 新课中计时指向实际下课时间 → 下课前进入独立提示 → 下课撤下。若上课回调晚到 15:18，课前卡片的系统到期时间仍为 15:10；迟到后使用真实下课时刻计算剩余时间，不会平移课程时间。已结束课程或已过期预览不能发布新的归零计时。

保留 1.0.5 的独立关键时点队列、持久化、后台诊断及系统设置入口，也保留静音规则和公开系统模板。若系统阻止所有后台回调，应用无法保证及时发布新的课中计时；本次到期保护让旧卡片具有正确的系统截止时间，不是绕过厂商限制的保活机制。

## 验证与实际限制

通过 flutter analyze、84 项 Flutter 测试、90 项 Kotlin/Robolectric 测试、ARM64 release 构建及 Android lint（无 Error/Fatal）。安装包版本 1.0.6（17）、原签名与 16 KB 对齐检查通过。

- 框架测试核对 Android 26 / 36 / 37 的课前通知 timeout：首次、临近上课和距上课 1 毫秒时，绝对到期均为上课时刻；预览可更早到期。
- Android 36 / 37 覆盖课前 → 课中 → 下课前 → 下课的完整链路。模拟旧 ID 延迟撤下，新课中通知继续存在。
- 直接把上课广播延迟 8 分钟送达，核对新通知真实下课时间及剩余时长；下课后才到达的广播不能恢复已结束通知。
- 核对过期课程/过期预览被拒绝，并保留既有计时连续运行、休眠恢复、下课独立提醒和后台队列测试。

Robolectric 不运行真正的 ColorOS SystemUI / NotificationManagerService。本次测试验证系统到期参数及应用状态切换，不声称实测了 OPPO 到期撤下的动画或缓存行为；仍需手机检查 15:10 这类边界。若系统没有遵循通知到期设置，也需结合展开后的通知及“最近后台触发”诊断。

安装 [1.0.6 APK](https://github.com/kitty191/schedule/raw/refs/heads/builds/android-v1.0.6/downloads/today-courses-v1.0.6-arm64.apk) 可直接覆盖旧版，无需先安装 1.0.5。保持原包名、签名和数据库，保留课程与设置。
